AWS has a tool for every stage of a migration: **building the business case**, **discovering** what you have, **moving** servers, databases and files, and **tracking** progress.

## Plan

| Tool | What it does |
|---|---|
| **Migration Evaluator** | Builds a **data-driven business case** (total cost of ownership, TCO) for moving to AWS |
| **AWS Application Discovery Service** | **Discovers on-premises servers**, their usage and the **dependencies** between them, to plan the migration |
| **AWS Migration Hub** | **One place to track** migration progress across tools. (Newer projects increasingly use **AWS Transform**, AWS's AI-powered migration and modernisation service) |

## Move servers

**AWS Application Migration Service (MGN)**: the main **rehosting** ("lift and shift") tool. It **continuously replicates** your servers to AWS and launches them as EC2 instances with minimal downtime.

## Move databases

**AWS Database Migration Service (DMS)** + **Schema Conversion Tool (SCT)** (Module 7): the source stays live during the move.

## Move files and data

| Tool | How | Use when |
|---|---|---|
| **AWS DataSync** | **Online** transfer from on-premises storage (NFS/SMB) to S3, EFS or FSx | You have a decent network connection |
| **AWS Transfer Family** | Managed **SFTP/FTPS/FTP** into S3 or EFS | Partners or systems that send files over SFTP |
| **AWS Snowball Edge** (Snow Family) | A rugged **physical device** shipped to you; load data, ship it back | **Huge** amounts of data (tens of TB to petabytes) and **limited bandwidth**; also edge computing |

(Snowcone and Snowmobile have been retired, but older question banks may still mention them: **Snowmobile** was an exabyte-scale data transfer **truck**.)

## Ongoing connectivity

**AWS Direct Connect** or **Site-to-Site VPN** (Module 5) for hybrid connections during and after the migration.

## How to choose a data-transfer method

```
lots of data + slow internet  → Snowball Edge (offline)
good network, files           → DataSync (online)
SFTP-based exchanges          → Transfer Family
whole servers                 → Application Migration Service
databases                     → DMS (+ SCT)
```

## Check yourself

1. Which service finds on-premises servers and the dependencies between them?
2. Which tool is the main choice for lift-and-shift of servers?
3. A company has 200 TB to move and a slow connection that would take months. What should it use?

### Answers

1. AWS Application Discovery Service.
2. AWS Application Migration Service (MGN).
3. AWS Snowball Edge.
