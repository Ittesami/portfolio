**Amazon S3 (Simple Storage Service)** stores **any amount** of data as **objects** in **buckets**. It's one of AWS's oldest and most used services: backups, images, videos, logs, data lakes and whole static websites live in S3.

## Buckets and objects

- A **bucket** is a container for objects. Bucket names are **globally unique** (across all AWS accounts), and each bucket lives in **one Region** you choose.
- An **object** is a file plus its metadata, identified by a **key** (its name, e.g. `photos/2026/cat.jpg`).
- A single object can be up to **5 TB**. Storage is effectively unlimited.

## Durability and availability

- **Durability: 99.999999999% (11 nines).** Store 10 million objects and you'd expect to lose one about every 10,000 years.
- S3 Standard keeps copies across **at least three Availability Zones** (except the One Zone classes).

Durability = "will my data still exist?" Availability = "can I reach it right now?". S3 is designed for very high levels of both.

## Key features

| Feature | What it does |
|---|---|
| **Versioning** | Keeps every version of an object, so you can recover from accidental deletes or overwrites |
| **Lifecycle policies** | Automatically move objects to cheaper storage classes, or delete them, after N days |
| **Bucket policies / access control** | Decide who can read and write. Buckets are **private by default** |
| **Encryption** | On by default for new objects |
| **Static website hosting** | Serve a website (HTML, CSS, JS, images) straight from a bucket |
| **Replication** | Copy objects automatically to a bucket in another Region (or the same one) |
| **S3 Object Lock** | **Write once, read many (WORM)**: objects can't be changed or deleted for a set time, for compliance |

## Worked scenarios

> Protect against users accidentally deleting important files. → Turn on **versioning**.

> Logs are needed for 30 days, rarely after 90, and must be deleted after a year. → **Lifecycle policy** (move to cheaper classes, then expire).

> Records must be impossible to change or delete for seven years, for regulators. → **S3 Object Lock**.

> Host a simple website with no servers. → **S3 static website hosting** (often with CloudFront in front).

## Exam traps

- Bucket names are **global**; the bucket's data lives in **one Region**.
- S3 is object storage: no OS disks, no databases.
- "11 nines" = durability, not availability.

## Check yourself

1. What's S3's designed durability?
2. Which feature protects objects from being overwritten or deleted by mistake?
3. Which feature automatically moves old objects to a cheaper storage class?

### Answers

1. 99.999999999% (11 nines).
2. Versioning (and for strict compliance, Object Lock).
3. Lifecycle policies.
