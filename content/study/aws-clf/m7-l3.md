Reading from memory is far faster than reading from disk. An **in-memory cache** keeps frequently requested data in RAM, **in front of** a database, so most reads never touch the database at all.

## Why cache?

Imagine the same "top 10 products" query running thousands of times a minute. Without a cache, the database does the same work thousands of times. With a cache:

```
app → cache: "top 10 products?"
        hit  → answer in microseconds (database untouched)
        miss → ask the database, store the answer in the cache for next time
```

Results: **faster responses** and **less load** on the database (often meaning a smaller, cheaper database).

## Amazon ElastiCache

A fully managed **in-memory cache**, supporting the popular engines **Valkey**, **Redis OSS** and **Memcached**. AWS handles setup, patching, monitoring and failure recovery.

Use it for:

- caching database query results,
- session stores (logged-in user sessions),
- leaderboards and real-time counters.

Keywords: "**speed up** frequently accessed data", "**reduce load** on the database", "sub-millisecond", "cache".

## Amazon MemoryDB

A **durable** in-memory **database** compatible with Redis/Valkey. Unlike a cache, it's meant to be your **primary** database, keeping data safe across failures, with in-memory speed.

## DAX (recap)

**DynamoDB Accelerator** is the in-memory cache **specifically for DynamoDB** (microsecond reads, no code changes to how you call DynamoDB).

| Need | Service |
|---|---|
| Cache in front of RDS or another database | **ElastiCache** |
| Cache in front of DynamoDB | **DAX** |
| Durable in-memory primary database | **MemoryDB** |

## Check yourself

1. An application repeats the same expensive query thousands of times a minute and the database is struggling. What should it add?
2. Which caching service is built specifically for DynamoDB?
3. What's the difference between ElastiCache and MemoryDB?

### Answers

1. An in-memory cache: Amazon ElastiCache.
2. DAX (DynamoDB Accelerator).
3. ElastiCache is a cache in front of another database; MemoryDB is a durable in-memory database you can use as your primary database.
