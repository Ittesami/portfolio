Most organisations use **many AWS accounts** (per team, per environment like dev/prod, per project). These services keep many accounts organised, secure and cost-tracked.

## AWS Organizations

**Centrally manage multiple AWS accounts.**

- **Organisational units (OUs):** group accounts, e.g. Dev, Prod, Finance.
- **Consolidated billing:** **one bill** for all accounts, and their usage is **combined** for volume discounts. It's a **free** feature.
- **Service control policies (SCPs):** set the **maximum permissions** for accounts or OUs.

```
Organization (management account)
 ├── OU: Prod     → SCP: "no one may leave the eu-west-2 Region"
 │    ├── account: shop-prod
 │    └── account: api-prod
 └── OU: Dev
      └── account: sandbox
```

### SCPs, precisely

SCPs **don't grant** permissions. They put a **ceiling** on what IAM policies in those accounts can allow, and the ceiling applies **even to the root user of member accounts**. A user needs **both** the IAM permission and an SCP that doesn't block it.

## AWS Control Tower

Quickly sets up and governs a **secure multi-account environment** (a "**landing zone**") with pre-configured **guardrails** (controls). It's built **on top of Organizations**. Keyword: "set up a new multi-account environment following best practices, quickly".

## Other governance tools

| Service | What it does |
|---|---|
| **AWS Service Catalog** | Admins publish **approved products** (e.g. pre-approved CloudFormation templates) for users to launch: self-service within the rules |
| **AWS License Manager** | Track **software licences** (Microsoft, Oracle…) across AWS and on-premises |
| **AWS Systems Manager** | Operational hub for **EC2 and on-premises servers at scale**: patching, running commands, **Parameter Store**, **Session Manager** (shell access without SSH keys) |
| **AWS Audit Manager** | Continuously **collects evidence** to prepare for audits |
| **Tags and AWS Resource Groups** | **Label** resources (e.g. `Project=Portfolio`, `Env=Prod`) to organise, automate and **track costs** |

## Worked scenarios

> A company with 40 accounts wants one bill and volume discounts. → **AWS Organizations** (consolidated billing).

> Prevent every account in the Dev OU from using expensive instance types, even admins. → A **service control policy**.

> Patch hundreds of EC2 instances and on-premises servers from one place. → **AWS Systems Manager**.

## Check yourself

1. Do SCPs grant permissions?
2. Which service sets up a best-practice multi-account landing zone with guardrails?
3. What does consolidated billing give you?

### Answers

1. No: they set the maximum permissions; IAM policies still have to grant them.
2. AWS Control Tower.
3. One bill for all accounts, with combined usage for volume discounts (free).
