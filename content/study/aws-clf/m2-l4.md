Real traffic goes up and down. **Amazon EC2 Auto Scaling** changes the **number** of instances to match demand, and **Elastic Load Balancing** spreads incoming requests across them. Together they give you elasticity and high availability.

## Amazon EC2 Auto Scaling

Auto Scaling adds instances when demand rises and removes them when it falls, so you're never paying for idle servers or running out of capacity. If an instance fails a health check, Auto Scaling **replaces** it.

An **Auto Scaling group** has three numbers:

| Setting | Meaning |
|---|---|
| **Minimum** | Never fewer than this, even at 3 a.m. |
| **Desired** | How many to run right now |
| **Maximum** | Never more than this: your **cost ceiling** |

```
min 2 ─── desired 4 ─── max 10
traffic rises → desired goes up (up to 10)
traffic falls → desired goes down (never below 2)
```

Two ways to scale:

- **Dynamic scaling** reacts to what's happening now, e.g. "add an instance when average CPU is above 70%".
- **Predictive scaling** uses forecasts to add capacity **before** an expected rise (e.g. every Monday morning).

## Elastic Load Balancing (ELB)

A load balancer is the **single front door** for your application. It receives every request and sends it to a healthy instance, spreading the work evenly, even across **multiple Availability Zones**. It stops sending traffic to unhealthy instances.

ELB is **managed**, **regional** and **highly available**: you don't run or patch the load balancer yourself.

| Type | Works at | Use for |
|---|---|---|
| **Application Load Balancer (ALB)** | Layer 7: HTTP/HTTPS | Web apps; can route by URL path or host (e.g. `/api` to one group, `/images` to another) |
| **Network Load Balancer (NLB)** | Layer 4: TCP/UDP | Extreme performance, millions of requests a second, static IPs |
| **Gateway Load Balancer** | Network appliances | Deploying third-party virtual appliances like firewalls |

## How they work together

```
users → Load Balancer → [ instance ][ instance ][ instance ]   ← Auto Scaling group
                          AZ a        AZ b        AZ a
```

Auto Scaling adds or removes instances; the load balancer automatically includes new ones and stops sending to removed or unhealthy ones.

## Worked scenario

> An application must handle sudden traffic spikes automatically and keep running if one instance fails, without overpaying at quiet times.

→ **EC2 Auto Scaling** behind an **Elastic Load Balancer**, across at least two Availability Zones.

## Check yourself

1. In an Auto Scaling group, what does the **maximum** capacity protect you from?
2. Which load balancer routes HTTP requests based on the URL path?
3. What does a load balancer do when an instance becomes unhealthy?

### Answers

1. Runaway costs: it caps how many instances can run.
2. The Application Load Balancer (layer 7).
3. It stops sending traffic to that instance and sends requests to the healthy ones (and Auto Scaling can replace it).
