EC2 instances can use two kinds of **block storage**: the **instance store** that comes with some instances, and **Amazon EBS** volumes. The big difference is what happens to your data when the instance stops.

## EC2 instance store

- Temporary block storage on disks **physically attached** to the host computer.
- Very fast.
- **Data is lost when the instance stops or terminates** (it's tied to that physical host).
- Use for **temporary data**: caches, scratch files, buffers, data that's copied elsewhere anyway.

## Amazon EBS (Elastic Block Store)

- **Network-attached virtual hard drives** (called **volumes**) for EC2.
- **Persists independently** of the instance: stop or even terminate the instance and the volume (if kept) still has your data.
- A volume lives in **one Availability Zone**, and attaches to instances **in that same AZ**.
- You choose the size and performance type.

### Volume types

| Type | Built on | Good for |
|---|---|---|
| **gp3** (general purpose SSD) | SSD | Most workloads, boot volumes |
| **io2** (provisioned IOPS SSD) | SSD | High-performance databases needing lots of IOPS |
| **st1** (throughput optimised HDD) | HDD | Big sequential workloads: logs, data processing |
| **sc1** (cold HDD) | HDD | Rarely accessed data at the lowest cost |

## EBS snapshots

A **snapshot** is a point-in-time **backup** of an EBS volume, stored in S3 behind the scenes.

- **Incremental:** after the first snapshot, only the blocks that changed are saved, so it's fast and cheap.
- You can create a **new volume from a snapshot**, including in **another AZ or Region**. That's how you move a volume or recover from a disaster.

```
volume (AZ a) ──snapshot──→ stored in S3 ──restore──→ new volume (AZ b or another Region)
```

## Side by side

| | Instance store | EBS |
|---|---|---|
| Survives stop / terminate | **No** | **Yes** |
| Attached | Physically, to the host | Over the network |
| Backups | You handle it | Snapshots |
| Use for | Temporary, scratch data | Anything you need to keep: OS, databases |

## Exam traps

- "Data must persist after the instance stops" → **EBS**, never instance store.
- An EBS volume can't be attached to an instance in a **different AZ**. Snapshot it and restore it there.

## Check yourself

1. What happens to instance store data when the instance is stopped?
2. How do you move an EBS volume's data to another Availability Zone?
3. Which EBS volume type suits a database needing very high IOPS?

### Answers

1. It's lost.
2. Take a snapshot, then create a new volume from it in the other AZ.
3. io2 (Provisioned IOPS SSD).
