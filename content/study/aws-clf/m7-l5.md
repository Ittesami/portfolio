Moving a database is risky: the business still needs it while the move happens. **AWS Database Migration Service (DMS)** moves databases to AWS **while the source keeps running**, so downtime is minimal.

## How DMS works

```
source database (still in use) ──continuous replication──→ target database on AWS
                                                   ↑ when ready, switch the app over
```

DMS copies the existing data, then keeps replicating **ongoing changes** until you switch your application to the new database.

## Two kinds of migration

| Kind | Meaning | Example | Extra tool |
|---|---|---|---|
| **Homogeneous** | Same database engine | MySQL → Amazon RDS for MySQL | None |
| **Heterogeneous** | Different engines | Oracle → Amazon Aurora | **AWS Schema Conversion Tool (SCT)** converts the schema and code first |

## Other uses of DMS

- **Development and test:** copy production data into a test database.
- **Database consolidation:** combine several databases into one.
- **Continuous replication:** keep a copy in sync for analytics or disaster recovery.

## Worked scenarios

> A company must move its Oracle database to Aurora PostgreSQL with minimal downtime. → **DMS**, plus the **Schema Conversion Tool** (heterogeneous).

> Move a MySQL database to Amazon RDS for MySQL while it stays live. → **DMS** (homogeneous; no schema conversion needed).
