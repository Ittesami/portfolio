These services **find problems**: threats in progress, vulnerabilities in your software, sensitive data in the wrong place. Their names are easy to mix up, so learn one line for each.

## The services

| Service | One-liner |
|---|---|
| **Amazon GuardDuty** | **Intelligent threat detection.** Uses ML on CloudTrail logs, VPC Flow Logs and DNS logs to spot threats such as compromised instances, crypto-mining or unusual API calls |
| **Amazon Inspector** | **Automated vulnerability scanning** of EC2 instances, container images and Lambda functions: known software vulnerabilities (CVEs) and unintended network exposure |
| **Amazon Macie** | **Discovers and protects sensitive data** (PII like names, card numbers) **in S3**, using ML |
| **AWS Security Hub** | A **central dashboard** that collects security findings from these services (and others) and runs best-practice checks |
| **Amazon Detective** | **Investigates the root cause** of security findings by analysing and visualising the related activity |

## How to tell them apart

Ask what the question is looking **for**:

- **Threats / malicious activity** happening in the account → **GuardDuty**
- **Vulnerabilities** in software or exposed ports → **Inspector**
- **Sensitive data** (PII) in **S3** → **Macie**
- **One place** to see all security findings → **Security Hub**
- **Why** did this happen? Dig into a finding → **Detective**

Memory hooks: Guard**Duty** is on guard duty watching for intruders; **Inspector** inspects your software for weak spots; **Macie** finds the personal data.

## Worked scenarios

> Detect that an EC2 instance is communicating with a known malicious IP. → **GuardDuty**.

> Scan EC2 instances for unpatched software vulnerabilities. → **Inspector**.

> Find S3 buckets containing customers' credit card numbers. → **Macie**.
