When an organisation moves to the cloud, it decides what to do with **each application**. AWS lists **seven strategies**, the "**7 Rs**". From least change to most:

## The 7 Rs

| Strategy | Meaning | Example |
|---|---|---|
| **Retire** | Turn off apps that are no longer needed | Decommission an unused reporting tool |
| **Retain** | Keep on-premises **for now** (not ready, recently upgraded, compliance) | A mainframe stays for two more years |
| **Rehost** ("lift and shift") | Move **as-is** to AWS, **no changes** | Copy a VM to EC2 using AWS Application Migration Service |
| **Relocate** | Move at the **hypervisor** level, with no new hardware and no app changes | VMware workloads to VMware-based environments on AWS |
| **Repurchase** ("drop and shop") | **Replace** with a different product, usually **SaaS** | Move from an on-premises CRM to Salesforce |
| **Replatform** ("lift, tinker and shift") | A **few cloud optimisations** without changing the core architecture | Self-managed MySQL → **Amazon RDS** |
| **Refactor / re-architect** | **Rewrite** to use cloud-native features; **most effort, most benefit** | A monolith → serverless microservices on Lambda |

## The pairs people mix up

- **Rehost vs Replatform:** rehost = **no** changes (VM straight onto EC2). Replatform = **small** tweaks, usually swapping a self-managed component for a **managed service** (e.g. moving the database to RDS) while the app stays the same.
- **Replatform vs Refactor:** replatform keeps the architecture; refactor **redesigns** it (microservices, serverless).
- **Repurchase:** you stop using your software and **buy** a different product (often SaaS).
- **Retire vs Retain:** retire = switch it off for good; retain = keep it where it is for now.

## Worked scenarios

> Migrate 300 servers quickly with no code changes. → **Rehost**.

> Move the app to EC2 but swap its self-managed database for Amazon RDS. → **Replatform**.

> Rebuild a monolith as serverless microservices to scale better. → **Refactor**.

> Replace the in-house email server with a SaaS email product. → **Repurchase**.

## Check yourself

1. Which strategy is also called "lift and shift"?
2. Moving a self-managed database to Amazon RDS during migration is which strategy?
3. Which strategy takes the most effort but gives the most cloud benefit?

### Answers

1. Rehost.
2. Replatform.
3. Refactor / re-architect.
