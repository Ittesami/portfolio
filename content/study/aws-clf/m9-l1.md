The **shared responsibility model** splits security between AWS and you. It's **guaranteed** to appear on the exam, usually several times.

## The one-line version

- **AWS** is responsible for security **OF** the cloud.
- **You** (the customer) are responsible for security **IN** the cloud.

## Who does what

| AWS: security OF the cloud | Customer: security IN the cloud |
|---|---|
| Physical data centres (guards, fences, power, cooling) | **Your data** (and how it's classified and encrypted) |
| Hardware and host servers | **Guest operating system** patching on EC2 |
| The hypervisor / virtualisation layer | **Applications** you install |
| The global network and infrastructure | **IAM**: users, permissions, MFA |
| The software that runs **managed** services | **Security group and network ACL** configuration |
| | **Encryption** choices (client-side, server-side) |
| | Firewall and network configuration |

## The split moves with the service

The **more managed** the service, the more AWS does:

| Service | Who patches the OS? | You still own |
|---|---|---|
| **EC2** (IaaS) | **You** | OS, apps, data, security groups, IAM |
| **RDS** (managed) | **AWS** (OS and database software) | Your data, who can access it, network settings |
| **Lambda / S3** (serverless/managed) | **AWS** | Your code or data, access permissions, encryption settings |

**You always own your data and who can access it**, whatever the service.

## Shared controls

Some controls apply to **both** sides, each at its own layer:

- **Patch management:** AWS patches the infrastructure; you patch your guest OS and apps.
- **Configuration management:** AWS configures its infrastructure; you configure your OS, databases and apps.
- **Awareness and training:** AWS trains its staff; you train yours.

## Worked scenarios

> Who patches the guest OS on an EC2 instance? → **The customer**.

> Who is responsible for the physical security of data centres? → **AWS**.

> Who patches the database engine on Amazon RDS? → **AWS**.

> Who configures security groups? → **The customer**.

## Exam traps

- "Customer data" is **always** the customer's responsibility, even on fully managed services.
- Physical anything (hardware, buildings, disk destruction) is AWS.
- Ask: is it **the infrastructure** (AWS) or **something I configure or put in** (me)?

## Check yourself

1. Under the shared responsibility model, who manages IAM permissions?
2. On Amazon RDS, who is responsible for patching the operating system?
3. Name one shared control.

### Answers

1. The customer.
2. AWS.
3. Patch management, configuration management, or awareness and training.
