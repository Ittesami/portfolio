**Cloud computing** is the on-demand delivery of IT resources (servers, storage, databases, software) **over the internet** with **pay-as-you-go** pricing. You rent what you need, when you need it, instead of buying and running your own hardware.

## The client–server model

A **client** (a browser or app) sends a request; a **server** processes it and sends a response. In the cloud, AWS provides the servers (for example an EC2 instance), so you never touch the hardware.

## Deployment models

| Model | What it means | Example |
|---|---|---|
| **Cloud-based** (all-in) | Everything runs in the cloud: new apps built there, or existing ones migrated | A start-up running entirely on AWS |
| **On-premises** (private cloud) | Your own data centre, often using virtualisation and resource-management tools | A bank's own server rooms |
| **Hybrid** | Cloud resources **connected** to on-premises infrastructure | New apps on AWS, a legacy payroll system kept in the office data centre |

Hybrid is common when some data **must** stay on-premises (regulations) or an old system can't move yet.

## The six advantages (learn these word for word)

These phrases appear in answer options all the time, so learn the exact wording:

1. **Trade fixed expense for variable expense.** No big upfront purchase (CapEx); pay only for what you use (OpEx).
2. **Benefit from massive economies of scale.** AWS's huge combined usage means lower prices per unit for everyone.
3. **Stop guessing capacity.** Scale up or down with real demand instead of over- or under-buying servers.
4. **Increase speed and agility.** New resources in minutes, so experiments are cheap and fast.
5. **Stop spending money running and maintaining data centres.** Focus on your customers, not on racking servers.
6. **Go global in minutes.** Deploy in Regions around the world with a few clicks.

> **Scenario:** a start-up doesn't want to spend a lot on servers before it knows the product will succeed. That's **trading fixed expense for variable expense**.

## Service models: who manages what

| Model | You get | You manage | Example |
|---|---|---|---|
| **IaaS** (Infrastructure) | Raw building blocks: virtual servers, storage, networking | The OS and everything above it | **Amazon EC2** |
| **PaaS** (Platform) | A platform to deploy code on | Just your application and data | **AWS Elastic Beanstalk** |
| **SaaS** (Software) | A finished product you simply use | Your data and settings | Gmail, Amazon WorkMail |

The further down the list, the **less control** and the **less work** for you. IaaS gives the **most control over the operating system**.

## Key words the exam uses

- **Elasticity:** **automatically** add resources when demand rises and remove them when it falls.
- **Scalability:** the ability to handle more load by adding resources (not necessarily automatic).
- **High availability:** the system keeps running when a component fails (maybe with some slowdown).
- **Fault tolerance:** keeps running with **no** degradation at all when something fails.
- **Multi-tenancy / resource pooling:** many customers share the same physical hardware, isolated from each other.
- **Measured service:** you pay for what you actually use.

## How you talk to AWS

Everything in AWS is an **API call**. You make those calls through:

| Tool | Best for |
|---|---|
| **AWS Management Console** (web, mobile app) | Learning, one-off tasks, visual overview |
| **AWS CLI** (command line) | Scripts and repeatable tasks from a terminal |
| **AWS SDKs** (Python boto3, JavaScript, Java…) | Calling AWS from your own application code |
| **Infrastructure as Code** (CloudFormation, CDK) | Creating whole environments from templates (Module 4) |

> **Scenario:** a developer wants to automate creating resources with repeatable scripts from a terminal → **AWS CLI**.

## Exam traps

- "Pay a fixed monthly fee regardless of usage" and "guaranteed 100% uptime" are **not** cloud advantages.
- The cloud doesn't remove **all** your security responsibilities (Module 9: shared responsibility).
- Elasticity is about **automatic** scaling, in both directions.

## Check yourself

1. A company keeps customer records in its own data centre for legal reasons but runs its website on AWS, connected to that data centre. Which deployment model is this?
2. Which service model gives the customer the most control over the operating system?
3. An online shop's servers automatically increase during a sale and decrease afterwards. Which cloud characteristic is this?

### Answers

1. Hybrid.
2. IaaS (for example Amazon EC2).
3. Elasticity.
