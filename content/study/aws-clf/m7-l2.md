**NoSQL** (non-relational) databases don't force data into fixed tables. They're built for **flexible structure**, **massive scale** and **very fast** simple lookups. AWS has a purpose-built NoSQL database for each data shape.

## Amazon DynamoDB (the one to know best)

A fully managed, **serverless key-value (and document) database**.

- **Single-digit-millisecond** performance at **any scale**.
- **Serverless:** no servers or versions to manage; it **scales automatically**.
- Data is stored as **items** (like rows) looked up by a **key**; each item can have different attributes.
- **DAX (DynamoDB Accelerator):** an in-memory cache for DynamoDB, taking reads down to **microseconds**.
- **Global tables:** automatic **multi-Region** replication for global apps.

```
key: user#42  →  { "name": "Ittehad", "streak": 5, "courses": ["dsa", "aws"] }
key: user#43  →  { "name": "Sam", "plan": "pro" }     ← different attributes is fine
```

Typical uses: user profiles, shopping carts, gaming leaderboards, session data, IoT data, anything needing fast lookups at huge scale.

## Other purpose-built NoSQL databases

| Service | Data model | Use for |
|---|---|---|
| **Amazon DocumentDB** | Documents (JSON), **MongoDB-compatible** | MongoDB workloads, content catalogues |
| **Amazon Neptune** | **Graph**: nodes and relationships | Social networks, recommendation engines, **fraud detection** (highly connected data) |
| **Amazon Keyspaces** | Wide-column, **Apache Cassandra-compatible** | Cassandra workloads |
| **Amazon Timestream** | **Time series** | IoT sensor data, metrics over time |

## Relational vs NoSQL

| | Relational (RDS/Aurora) | NoSQL (DynamoDB) |
|---|---|---|
| Structure | Fixed schema: tables, columns | Flexible: each item can differ |
| Queries | Rich SQL, joins across tables | Fast lookups by key |
| Scaling | Mostly vertical, plus read replicas | Horizontal, practically unlimited |
| Best for | Transactions with complex relationships | Huge scale, simple fast access |

## Worked scenarios

> A gaming app needs millisecond responses for millions of players with no servers to manage. → **DynamoDB**.

> A company is moving its MongoDB database to a managed AWS service. → **DocumentDB**.

> A bank wants to find fraud rings by analysing relationships between accounts. → **Neptune** (graph).
