Clicking through the console is fine for learning, but real environments are built with **Infrastructure as Code (IaC)**: you describe your infrastructure in files, and a tool creates it for you, identically, every time.

## AWS CloudFormation

You write a **template** (JSON or YAML) describing the resources you want: VPCs, EC2 instances, databases, load balancers. CloudFormation creates them all together as a **stack**, in the right order.

```yaml
Resources:
  MyBucket:
    Type: AWS::S3::Bucket
  MyServer:
    Type: AWS::EC2::Instance
    Properties:
      InstanceType: t3.micro
      ImageId: ami-0123456789abcdef0
```

- The same template builds the same environment in **any Region or account**.
- Update the template and CloudFormation works out what to change.
- Delete the stack and everything it created is removed.
- **CloudFormation itself is free**: you pay only for the resources it creates.

## AWS CDK (Cloud Development Kit)

Write your infrastructure in a **programming language** (TypeScript, Python, Java…) instead of YAML. The CDK turns your code into a CloudFormation template behind the scenes. Good for developers who want loops, functions and type checking.

## Why IaC (the benefits the exam wants)

- **Repeatable and consistent:** no "someone forgot a setting" in production.
- **Version-controlled:** templates live in Git, so changes are reviewed and can be rolled back.
- **Fewer manual errors.**
- **Easy to replicate:** copy an environment to another Region for **disaster recovery** or to create test environments.
- **Automation:** fits the Well-Architected principle "perform operations as code" (Module 13).

## Worked scenario

> A company needs to create identical test and production environments in three Regions, quickly and without manual mistakes.

→ **AWS CloudFormation** (Infrastructure as Code).
