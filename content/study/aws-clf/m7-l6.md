This lesson pulls Module 7 together. AWS's message is "**purpose-built databases**": pick the database that fits the **shape of your data** and how you use it, rather than one database for everything.

## The decision table

| Need | Answer |
|---|---|
| Managed MySQL, PostgreSQL, MariaDB, Oracle, SQL Server or Db2 | **Amazon RDS** |
| High-performance, highly available relational, MySQL/PostgreSQL-compatible | **Amazon Aurora** |
| Serverless key-value, millisecond latency at massive scale | **Amazon DynamoDB** |
| Data warehouse, BI over huge historical data | **Amazon Redshift** |
| MongoDB workloads | **Amazon DocumentDB** |
| Relationships / graph (social, fraud, recommendations) | **Amazon Neptune** |
| Apache Cassandra | **Amazon Keyspaces** |
| Time-series (IoT, metrics) | **Amazon Timestream** |
| Cache to speed up reads | **Amazon ElastiCache** (DAX for DynamoDB) |
| Move a database to AWS with minimal downtime | **AWS DMS** |

## Three questions to ask

1. **Is it analytics over history?** → Redshift.
2. **Does the data have a fixed structure with relationships and transactions?** → RDS or Aurora (Aurora for "high performance", "MySQL-compatible at lower cost").
3. **Is it simple fast lookups at huge scale, or "serverless"?** → DynamoDB.

Then look for the special data shapes: documents/MongoDB, graph, time series, Cassandra.

## Managed vs on EC2

Running a database **on EC2** gives you full control (any engine, any version, OS access) but **you** do the patching, backups and scaling. "**Least operational overhead**" or "**managed**" in the question → RDS, Aurora or DynamoDB.

## Check yourself

1. A start-up needs a database that scales automatically with no servers and responds in milliseconds. Which?
2. A recommendation engine stores "users who bought X also bought Y" relationships. Which?
3. A company must run a database version AWS doesn't offer on RDS and needs OS access. Where?

### Answers

1. Amazon DynamoDB.
2. Amazon Neptune (graph).
3. On Amazon EC2 (self-managed).
