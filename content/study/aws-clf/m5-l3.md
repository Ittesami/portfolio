A VPC has two layers of firewall: **network ACLs** at the **subnet** border and **security groups** at each **instance**. The exam loves asking you to tell them apart.

## Side by side

| | Security group | Network ACL (NACL) |
|---|---|---|
| Applies to | The **instance** (its network interface) | The **subnet** |
| State | **Stateful**: if a request is allowed in, the reply is automatically allowed out | **Stateless**: return traffic must be explicitly allowed too |
| Rules | **Allow only** | **Allow and deny** |
| Evaluation | All rules considered together | Rules checked **in number order**; the first match wins |
| Default | Denies all inbound, allows all outbound | The default NACL **allows** all inbound and outbound |

## Stateful vs stateless, explained

Your browser asks a web server for a page (request in on port 443), and the server sends the page back (response out).

- **Security group (stateful):** you allow inbound 443 once. It **remembers** the conversation, so the response is automatically allowed out.
- **NACL (stateless):** it doesn't remember. You must allow inbound 443 **and** the outbound response traffic.

## The memory trick

A packet entering your instance passes two checkpoints:

```
internet → [ NACL: subnet border ] → [ security group: instance door ] → instance
```

- The **NACL** is **passport control** at the border. It checks everyone, **in both directions**, every time, and can **turn people away** (deny rules).
- The **security group** is the **doorman** at the building. He only has a guest list (allow rules) and **remembers** you on the way out.

## When to use which

- Normal case: control access with **security groups** (e.g. "the database accepts traffic only from the app servers' security group").
- Need to **explicitly block** a specific IP address or range? Only a **NACL** can deny.

## Worked scenario

> A company must block all traffic from one malicious IP address to an entire subnet.

Security groups can't deny, so → **network ACL** with a deny rule.

## Exam traps

- "Stateful" → security group. "Stateless" → NACL.
- "Deny rule" → NACL only.
- Security groups are configured by the **customer** (shared responsibility).

## Check yourself

1. Which firewall works at the subnet level?
2. Can a security group block a specific IP address with a deny rule?
3. You allowed inbound HTTPS in a NACL but responses aren't getting back to users. Why?

### Answers

1. The network ACL.
2. No: security groups only have allow rules. Use a NACL to deny.
3. NACLs are stateless: you must also allow the outbound return traffic.
