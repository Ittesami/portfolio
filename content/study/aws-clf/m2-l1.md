**Amazon EC2 (Elastic Compute Cloud)** gives you **virtual servers**, called **instances**, in the cloud. You launch one in minutes, choose its size, stop it when you don't need it, and pay only while it runs. EC2 is AWS's classic **IaaS** service.

## Why it matters

Buying a physical server means weeks of waiting, a big upfront cost, and guessing how big it needs to be. With EC2 you get a server in minutes, change its size later, and pay as you go.

## Key ideas

- **Instance:** one virtual server. You pick the CPU, memory, storage and network size (the instance type, next lesson).
- **AMI (Amazon Machine Image):** the **template** an instance starts from: the operating system plus any pre-installed software. Launch ten instances from the same AMI and they're identical.
- **Multi-tenancy:** your instance shares a physical host with other customers' instances. The **hypervisor** keeps them isolated; they can't see each other.
- **Billing:** you pay while the instance is running (per second for Linux, with a one-minute minimum). A **stopped** instance doesn't charge for compute, but its attached EBS storage still costs.

## What you manage vs what AWS manages

Because EC2 is IaaS, you have lots of control and lots of responsibility:

| You | AWS |
|---|---|
| Choose the OS, **patch** it, install software | Physical servers, data centres |
| Configure the **security group** (firewall) | The hypervisor |
| Your data and applications | The global network |

This split is the **shared responsibility model** (Module 9). It comes up a lot.

## Scaling an instance

- **Vertical scaling (scale up):** make one instance **bigger** (more CPU/memory). Simple, but there's a limit and usually a short restart.
- **Horizontal scaling (scale out):** add **more** instances and share the load between them. Better for availability: if one fails, the others carry on. (Auto Scaling and load balancing do this, lesson 4.)

## Worked scenario

> A company needs full control of the operating system to install custom software for a long-running application.

That's **EC2**: you control the OS. A serverless option like Lambda gives you no OS access at all.

## Exam traps

- EC2 = **you** patch the guest operating system. On managed services (RDS, Lambda) AWS does.
- An **AMI** is a template, not a running server.
- "Resizable compute capacity" in an answer usually means EC2.

## Check yourself

1. What is an AMI?
2. Who is responsible for patching the operating system of an EC2 instance?
3. What's the difference between scaling up and scaling out?

### Answers

1. Amazon Machine Image: the template (OS + software) that an EC2 instance is launched from.
2. The customer.
3. Scaling up makes one instance bigger (vertical); scaling out adds more instances (horizontal).
