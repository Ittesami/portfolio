A **container** packages your code **together with everything it needs** (libraries, runtime, settings) so it runs exactly the same on a laptop, a test server or in production. Docker is the most common container tool. Containers are lighter than virtual machines and start in seconds.

## Why containers

"It works on my machine" stops being a problem: the container **is** the machine environment. They're ideal for microservices, where each service ships as its own container.

## Running many containers: orchestration

Once you have dozens of containers, something must decide where they run, restart failed ones and scale them. That's **container orchestration**.

| Service | What it is | Choose it when… |
|---|---|---|
| **Amazon ECS** (Elastic Container Service) | AWS's **own** container orchestrator | you want a simple AWS-native way to run containers |
| **Amazon EKS** (Elastic Kubernetes Service) | **Managed Kubernetes** | the question mentions **Kubernetes** |
| **AWS Fargate** | A **serverless** compute engine for containers; works with ECS and EKS | you don't want to manage any servers for your containers |
| **Amazon ECR** (Elastic Container Registry) | Stores and manages your **container images** | you need somewhere to keep images |

## Where the containers run

ECS and EKS need compute underneath. Two choices:

- **On EC2 instances:** you manage those instances (patching, scaling). More control.
- **On Fargate:** AWS runs the compute for you. No servers to manage: **serverless containers**.

```
ECS or EKS  (decides what runs where)
     │
     ├── on EC2 instances  → you manage the servers
     └── on Fargate        → AWS manages the servers
```

## Worked scenarios

> A company wants to run containers without provisioning or managing servers.
→ **AWS Fargate** (with ECS or EKS).

> A team already uses Kubernetes on-premises and wants a managed version on AWS.
→ **Amazon EKS**.

## Exam traps

- **Fargate is not an orchestrator.** It's the serverless place containers run; ECS or EKS still orchestrates.
- "Kubernetes" in the question → **EKS**, not ECS.
- ECR stores images; it doesn't run anything.

## Check yourself

1. Which service runs containers without you managing servers?
2. Which service should a company choose if it wants to keep using Kubernetes?
3. Where do you store Docker images on AWS?

### Answers

1. AWS Fargate.
2. Amazon EKS.
3. Amazon ECR.
