Not everything moves to the cloud at once. These services connect **on-premises storage** to AWS, **back up** data across services, and keep you running after a disaster.

## AWS Storage Gateway

**Hybrid storage:** on-premises applications use cloud storage as if it were local, with a local cache for fast access to recent data.

| Gateway type | Presents to your apps | Stored in |
|---|---|---|
| **File Gateway** | File shares (NFS/SMB) | S3 (as objects) |
| **Volume Gateway** | Block volumes (iSCSI) | AWS, with EBS snapshots |
| **Tape Gateway** | A virtual tape library for backup software | S3 / Glacier, replacing physical tapes |

Keywords: "**on-premises** applications", "**hybrid**", "replace tape backups", "low-latency local access to cloud storage".

## AWS Backup

**Centrally manage and automate backups** across many services (EC2, EBS, RDS, DynamoDB, EFS, FSx…) from **one place**: backup plans, schedules, retention rules and reports. Instead of setting up backups service by service.

## AWS Elastic Disaster Recovery

Continuously **replicates servers** (on-premises or in the cloud) into AWS, so after a failure you can **recover them quickly** in AWS with minimal data loss.

## Moving data in

For moving data **into** AWS (covered fully in Module 12):

- **AWS DataSync:** fast **online** transfer of files from on-premises storage to S3, EFS or FSx.
- **AWS Snowball Edge** (Snow Family): a rugged **physical device** shipped to you for **offline** transfer of huge amounts of data when the network is too slow.

## Worked scenarios

> A company wants on-premises apps to store files in S3 while keeping fast local access to recent files. → **Storage Gateway (File Gateway)**.

> Backups for EC2, RDS and DynamoDB must be managed from one place with one retention policy. → **AWS Backup**.

> Replace physical backup tapes with cloud storage, without changing the backup software. → **Tape Gateway**.
