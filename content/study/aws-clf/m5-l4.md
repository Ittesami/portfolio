**DNS** (the Domain Name System) is the internet's phone book: it turns names like `example.com` into IP addresses computers can connect to. On AWS that's **Amazon Route 53**, usually working together with **CloudFront** at the edge.

## Amazon Route 53

A highly available, scalable **DNS service** (named after port 53, the DNS port). It does three jobs:

1. **Registers domain names** (buy `my-site.com`).
2. **Translates names to IP addresses** (DNS resolution).
3. **Checks the health** of your endpoints and **routes traffic** to healthy ones.

### Routing policies

How Route 53 decides which address to answer with:

| Policy | Sends users… | Use for |
|---|---|---|
| **Simple** | to one resource | A single web server |
| **Weighted** | split by percentages (e.g. 90% / 10%) | Testing a new version on a few users |
| **Latency-based** | to the Region with the **lowest latency** for them | Global apps, fastest experience |
| **Failover** | to a backup when the primary fails a health check (active/passive) | Disaster recovery |
| **Geolocation** | based on the user's **location** (country/continent) | Localised content, legal restrictions |
| **Geoproximity** | based on the distance to resources (adjustable bias) | Shifting traffic between Regions |
| **Multivalue answer** | several healthy addresses at once | Simple load spreading |

## How it fits together

```
user types www.example.com
   → Route 53 answers with the CloudFront address
   → CloudFront serves cached content from a nearby edge location
   → on a cache miss, CloudFront fetches from the origin (S3 bucket or load balancer)
```

- **CloudFront** (Module 4) often sits in front of **S3** or a **load balancer**.
- **Route 53** points your domain name at CloudFront.
- **AWS Shield** (Module 9) automatically protects Route 53 and CloudFront from DDoS attacks.

## Worked scenarios

> Users around the world should be sent to whichever Region responds fastest for them. → Route 53 **latency-based** routing.

> If the main site fails, users should automatically go to a backup site. → Route 53 **failover** routing with health checks.

> Show different content to users in France and Germany. → **Geolocation** routing.

## Check yourself

1. Which service registers domain names on AWS?
2. A company wants to send 10% of users to a new version of its site. Which routing policy?
3. What usually sits between Route 53 and an S3-hosted website to make it faster worldwide?

### Answers

1. Amazon Route 53.
2. Weighted routing.
3. Amazon CloudFront (the CDN).
