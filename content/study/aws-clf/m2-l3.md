How you **pay** for EC2 is one of the most tested topics on the whole exam. The rule of thumb: the more you **commit** (or the more interruption you **accept**), the less you pay.

## The pricing options

| Option | How it works | Discount | Best for |
|---|---|---|---|
| **On-Demand** | Pay per second/hour, no commitment | None | Short-term, unpredictable workloads that **can't be interrupted**; testing; trying something new |
| **Savings Plans** | Commit to spending a set **$ per hour** for **1 or 3 years** | Up to ~72% | Steady usage where you want **flexibility** |
| **Reserved Instances (RIs)** | Commit to a **specific instance configuration** for **1 or 3 years** | Up to ~72% | Steady, **predictable** workloads, e.g. a database that runs 24/7 |
| **Spot Instances** | Use AWS's **spare** capacity; AWS can take it back with a **2-minute warning** | Up to **90%** | Flexible, **interruptible** jobs: batch processing, data analysis, CI tests |
| **Dedicated Hosts** | A **whole physical server** just for you, with visibility of its sockets and cores | Most expensive | **Bring-your-own licences** tied to sockets/cores; strict compliance |
| **Dedicated Instances** | Your instances run on hardware not shared with other customers (no host-level visibility) | Higher | Isolation requirements |
| **Capacity Reservations** | Reserve capacity in a specific Availability Zone, billed at On-Demand rates | None | Guaranteeing capacity for a known event |

## Savings Plans vs Reserved Instances

Both need a 1- or 3-year commitment and give similar discounts. The difference is **flexibility**:

- **Reserved Instances** lock you into a specific instance setup (Standard RIs) or allow some changes (Convertible RIs, smaller discount). You can pay **all upfront, partial upfront or no upfront** (more upfront = bigger discount).
- **Savings Plans** commit you to a **dollar amount per hour**. **Compute Savings Plans** apply across instance families, sizes and Regions, and also cover **AWS Fargate and AWS Lambda**.

If the question says "flexibility" or mentions Lambda/Fargate → **Savings Plans**.

## Spot Instances in practice

Spot is cheap because you're using capacity AWS hasn't sold. When AWS needs it back, your instance gets a **2-minute warning** and is stopped or terminated. So only use Spot for work that can **pause and resume** or be **retried**.

## The decision in one table

| The question says… | Answer |
|---|---|
| "can be interrupted", "flexible start and end times", "lowest cost" | **Spot** |
| "steady state", "1 or 3 years", "predictable", "always on" | **Savings Plans** or **Reserved Instances** |
| "short-term", "unpredictable", "cannot be interrupted", "testing" | **On-Demand** |
| "server-bound software licences", "sockets/cores", "physical server" | **Dedicated Hosts** |

## Worked scenario

> A company runs a nightly data-processing job that can be stopped and restarted without problems, and wants the lowest cost.

Interruptible + lowest cost → **Spot Instances**.

## Exam traps

- Spot is **not** for databases or anything that can't be interrupted.
- Dedicated **Hosts** (physical server, licence visibility) vs Dedicated **Instances** (isolated hardware, no host visibility): "licences" or "sockets/cores" means Hosts.

## Check yourself

1. A database runs constantly for the next three years. Which option is most cost-effective?
2. Which option gives the biggest discount, and what's the catch?
3. A company must use its existing per-socket software licences. Which option?

### Answers

1. A Reserved Instance or a Savings Plan with a 3-year term (steady, predictable usage).
2. Spot Instances (up to 90% off). AWS can reclaim them with a 2-minute warning, so the work must tolerate interruption.
3. Dedicated Hosts.
