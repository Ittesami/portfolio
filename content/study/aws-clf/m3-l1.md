**Serverless** means you **don't provision or manage any servers**. AWS handles the capacity, scaling, patching and availability; you only bring your code (or configuration) and pay for what actually runs. There are still servers, but they're AWS's problem.

## AWS Lambda

Lambda runs your code **in response to events**, then stops.

- **Triggers:** a file uploaded to S3, an HTTP request through API Gateway, a change in a DynamoDB table, a schedule ("every day at 2 a.m."), a message in a queue, and many more.
- **Billing:** per request and per millisecond the code runs. If nothing happens, you pay nothing.
- **Scaling:** automatic, from zero to thousands of copies running in parallel.
- **Limit:** a single run (invocation) can last at most **15 minutes**. So Lambda is for **short, event-driven** tasks, not long-running jobs.

```
photo uploaded to S3 ──event──→ Lambda: make a thumbnail ──→ thumbnail saved to S3
```

## Amazon API Gateway

Create, publish and secure **APIs** at any scale. Often the **front door** for Lambda: a request to `https://api.example.com/orders` triggers a Lambda function that returns the response.

## AWS Step Functions

**Orchestrates** several Lambda functions and other services into a **visual workflow** with steps, branches, retries and waits. Use it when a process has many stages (e.g. order → payment → shipping → email).

## Serverless vs EC2

| | EC2 | Lambda (serverless) |
|---|---|---|
| Servers to manage | Yes: OS, patching, scaling | **None** |
| Pricing | While the instance runs | Per request + run time |
| Long-running processes | Yes | No (15-minute limit) |
| OS access | Full | None |
| Idle cost | Yes (if running) | **Zero** |

## Worked scenario

> When a customer uploads a document, it must be resized automatically. The company wants no servers to manage and to pay only when uploads happen.

→ **AWS Lambda**, triggered by the S3 upload.

## Exam traps

- "Least operational overhead", "no servers to manage", "pay only when code runs" → serverless (Lambda).
- A job that runs for **hours** can't be a single Lambda function (15-minute limit): use EC2, AWS Batch or Fargate instead.
