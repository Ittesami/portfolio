S3 has several **storage classes** that trade **storage price** against **how fast and how cheaply** you can get data back. The exam gives you an access pattern and asks for the cheapest class that still meets it.

## The classes

| Class | Use when | Notes |
|---|---|---|
| **S3 Standard** | Data accessed **frequently** | Highest storage cost, no retrieval fee, 3+ AZs |
| **S3 Intelligent-Tiering** | Access pattern **unknown or changing** | Automatically moves objects between tiers; small monitoring fee per object |
| **S3 Standard-IA** (Infrequent Access) | Accessed **rarely**, but needed **fast** when it is | Cheaper storage, but a fee per GB retrieved; 3+ AZs |
| **S3 One Zone-IA** | Infrequent data that's **easy to re-create** | Only **one AZ**, about 20% cheaper than Standard-IA |
| **S3 Express One Zone** | The **highest performance**, single-digit-millisecond latency | One AZ |
| **S3 Glacier Instant Retrieval** | Archive accessed about **once a quarter** that must come back in **milliseconds** | Archive pricing, instant access |
| **S3 Glacier Flexible Retrieval** | Archive where retrieval in **minutes to ~12 hours** is fine | Cheaper still |
| **S3 Glacier Deep Archive** | **Lowest-cost** long-term archive (7–10 years, compliance) | Retrieval within **~12–48 hours** |

## The pattern

```
access often ←───────────────────────────────────→ access almost never
Standard → Standard-IA → Glacier Instant → Glacier Flexible → Deep Archive
 most expensive to store                         cheapest to store
 cheapest/fastest to retrieve               slowest/costliest to retrieve
```

## Picking the right one (exam keywords)

| The question says… | Class |
|---|---|
| "frequently accessed" | Standard |
| "unknown" or "unpredictable" access pattern | Intelligent-Tiering |
| "infrequently accessed but needs immediate access" | Standard-IA |
| "infrequent", "can be re-created", "lowest cost", single AZ is OK | One Zone-IA |
| "archive" + "**milliseconds**" | Glacier Instant Retrieval |
| "archive" + "minutes or hours is fine" | Glacier Flexible Retrieval |
| "**cheapest** long-term archive", "7–10 years", "retrieval within 48 hours" | Glacier Deep Archive |

## Combining classes with lifecycle policies

A typical policy for logs:

1. Days 0–30: **Standard** (often read).
2. Day 30: move to **Standard-IA**.
3. Day 90: move to **Glacier Flexible Retrieval**.
4. Day 365: **delete**.

## Exam traps

- "Milliseconds" archive → **Glacier Instant Retrieval**. The cheapest archive → **Deep Archive**.
- One Zone classes lose data if that AZ is destroyed, so only use them for data you can re-create.

## Check yourself

1. Medical images are opened about once a month, must load instantly when a doctor opens them, and must survive the loss of an Availability Zone. The company wants a lower storage cost than S3 Standard. Which class?
2. A company must keep tax records for 10 years at the lowest possible cost; retrieving them within two days is fine. Which class?
3. The access pattern of a new data set is unknown. Which class?

### Answers

1. S3 Standard-IA: infrequent access, immediate retrieval, and stored across 3+ AZs (One Zone-IA wouldn't survive losing its AZ). If access were only about once a quarter, Glacier Instant Retrieval would be cheaper.
2. S3 Glacier Deep Archive.
3. S3 Intelligent-Tiering.
