A **relational database** stores data in **tables** of rows and columns, with **relationships** between tables, and is queried with **SQL**. It's the right choice for structured data and **transactions** (orders, payments, bookings).

```
Customers                  Orders
id | name                  id | customer_id | total
1  | Ittehad    ←───────── 7  | 1           | £20
```

## Three ways to run one on AWS

1. **On-premises:** you do everything.
2. **On EC2:** AWS runs the hardware, but you install, patch, back up and scale the database yourself.
3. **A managed service (Amazon RDS / Aurora):** AWS does the undifferentiated heavy lifting.

## Amazon RDS (Relational Database Service)

A **managed** relational database. AWS automates:

- hardware provisioning and database setup,
- **patching** the database software,
- **automated backups** and point-in-time recovery,
- **Multi-AZ** deployments: a **standby copy in another AZ**; if the primary fails, RDS **fails over** automatically. (For **availability**.)
- **Read replicas:** read-only copies that take reading load off the primary. (For **performance**.)

**Engines:** Amazon Aurora, MySQL, PostgreSQL, MariaDB, Oracle, Microsoft SQL Server, IBM Db2.

You still manage: your data, schema, queries, and who can access the database.

## Amazon Aurora

AWS's own **enterprise-class** relational database, compatible with **MySQL and PostgreSQL**:

- up to **5× faster than MySQL** and **3× faster than PostgreSQL**,
- about **1/10 the cost** of commercial databases,
- storage keeps **6 copies of your data across 3 AZs**,
- up to **15 read replicas**,
- **Aurora Serverless** scales capacity up and down automatically.

## Multi-AZ vs read replicas (don't mix them up)

| | Multi-AZ | Read replica |
|---|---|---|
| Purpose | **High availability**, automatic failover | **Scale reads**, performance |
| Serves traffic normally? | No: the standby waits | Yes: handles read queries |
| Keyword | "fail over", "if the primary fails" | "many read requests", "reporting queries slowing the database" |

## Worked scenarios

> A company wants MySQL without managing patching and backups. → **Amazon RDS** (MySQL).

> It needs a highly available, high-performance MySQL-compatible database at lower cost than commercial databases. → **Amazon Aurora**.

> Reporting queries are slowing down the production database. → **Read replicas**.

## Check yourself

1. Which RDS feature keeps a standby copy in another AZ for automatic failover?
2. How many copies of data does Aurora keep, and across how many AZs?
3. On RDS, who patches the database software?

### Answers

1. Multi-AZ deployment.
2. 6 copies across 3 Availability Zones.
3. AWS (it's a managed service).
