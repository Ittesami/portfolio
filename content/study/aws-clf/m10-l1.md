Three services watch your account, and they're the most mixed-up trio on the exam: **CloudWatch**, **CloudTrail** and **Config**. Each answers a different **question**.

## The big three

| Service | The question it answers | Details |
|---|---|---|
| **Amazon CloudWatch** | **How are my resources performing?** | **Metrics** (CPU, latency, errors), **alarms** (trigger SNS notifications or Auto Scaling when a threshold is crossed), **dashboards**, and **CloudWatch Logs** for application logs |
| **AWS CloudTrail** | **Who did what, when, and from where?** | Records **API calls** and account activity: which user, what action, what time, from which IP address. For **auditing** and security investigations. **CloudTrail Insights** spots unusual API activity |
| **AWS Config** | **What did my resource's configuration look like, and is it compliant?** | Records the **configuration history** of resources and every change. **Config rules** check compliance (e.g. "all S3 buckets must be encrypted") |

## Telling them apart

| The question says… | Answer |
|---|---|
| "CPU utilisation", "metrics", "alarm when…", "dashboard", "performance", "application logs" | **CloudWatch** |
| "**who** deleted / changed / launched", "API calls", "audit trail", "user activity" | **CloudTrail** |
| "configuration **history**", "what did it look like last week", "**compliance** rules for resources" | **Config** |

Memory hooks:

- Cloud**Watch** = **watch** the performance.
- Cloud**Trail** = the **trail** of footsteps: who went where.
- **Config** = **configuration**.

## Worked scenarios

> An administrator needs to know who terminated an EC2 instance yesterday. → **CloudTrail**.

> Send an email when an instance's CPU goes above 80%. → **CloudWatch alarm** (with SNS).

> Check that every EBS volume stays encrypted and record any changes. → **AWS Config** (with a Config rule).

## Good to know

- CloudTrail is on by default, and its **Event history** shows the last 90 days of management activity. Create a **trail** to keep logs longer (in S3).
- CloudWatch alarms can trigger **Auto Scaling** actions.

## Check yourself

1. Which service records the API calls made in your account?
2. Which service would trigger an alarm when latency gets too high?
3. Which service shows how a security group's rules have changed over time?

### Answers

1. AWS CloudTrail.
2. Amazon CloudWatch.
3. AWS Config.
