You don't need to build a model to use one, but knowing **how it works** explains nearly every strange behaviour you'll meet: why it miscounts letters, why long prompts cost more, why it "makes things up".

## The one-sentence version

A large language model (LLM) is a neural network trained to **predict the next token** given all the tokens before it. Everything else (chat, code, reasoning, tool use) is built on that single ability.

## Step 1: text becomes tokens

Models don't read letters or words. A **tokenizer** splits text into **tokens**: common words are one token, rarer words split into pieces.

```
"Tokenization is surprisingly useful"
→ ["Token", "ization", " is", " surprisingly", " useful"]
```

Rules of thumb for English: **1 token ≈ 4 characters ≈ ¾ of a word**. 1,000 words ≈ 1,300 tokens.

Why it matters:

- **You pay per token**, input and output separately.
- **Limits are in tokens** (context window, `max_tokens`).
- **Letter-level tasks are hard**: "how many r's in strawberry" asks about letters the model never sees directly.
- Different models can use **different tokenizers**, so the same text can be a different number of tokens.

## Step 2: tokens become embeddings

Each token ID is looked up in a table and turned into a **vector** (a list of thousands of numbers), its **embedding**. Similar meanings end up as nearby vectors: "king" sits near "queen", "Paris" near "London".

Position matters too ("dog bites man" vs "man bites dog"), so position information is added to each vector.

## Step 3: attention mixes context in

The core of the **transformer** is **self-attention**. For each token, the model asks: *which other tokens should I look at to understand this one?*

```
"The trophy didn't fit in the suitcase because it was too big."
                                                 ↑
                   attention links "it" strongly to "trophy"
```

Mechanically, each token makes three vectors: a **query** (what I'm looking for), a **key** (what I contain) and a **value** (what I pass on). Scores = query · key for every pair, softmaxed into weights, then each token takes a weighted mix of the values. Many **attention heads** do this in parallel, each learning a different kind of relationship, and dozens of **layers** stack on top of each other.

Cost: attention compares every token with every earlier token, which is why **long contexts cost more** compute and time.

## Step 4: predict the next token

The final layer outputs a **probability for every token in the vocabulary**:

```
"The capital of France is" → " Paris" 0.92, " a" 0.03, " the" 0.02, ...
```

One token is picked, appended to the input, and the whole thing runs again. That loop is **generation**. It's why responses stream out word by word, and why **output tokens cost more than input tokens** (each one needs its own pass).

## How a base model becomes an assistant

| Stage | Data | Result |
|---|---|---|
| **Pre-training** | Trillions of tokens of text and code | Knows language and facts; continues text, doesn't follow instructions |
| **Fine-tuning on instructions** | Example conversations | Answers questions, follows instructions |
| **Reinforcement learning** (from human and AI feedback) | Preferred vs rejected answers | Helpful, honest, refuses harmful requests |

Modern models are also trained to **think before answering** (reasoning), which the API exposes as **thinking** (API module).

## What this explains

- **Hallucination:** the model produces *likely* text, not *checked* text. If it doesn't know, a plausible-sounding answer can still score high. Fix: give it the facts (RAG), let it say "I don't know", ask for citations.
- **Knowledge cutoff:** it only knows what was in its training data. Fix: tools like web search.
- **No memory between calls:** the API is stateless; the model only sees what you send in this request.
- **Prompt sensitivity:** small wording changes shift the probabilities. Fix: clear instructions and evals.

## Check yourself

1. Roughly how many tokens is a 750-word essay?
2. Why are output tokens priced higher than input tokens?
3. What problem does attention solve?
4. Why does a model sometimes state wrong facts confidently?

### Answers

1. About 1,000 tokens (¾ of a word per token).
2. Input tokens are processed together in one parallel pass; each output token needs its own forward pass through the network.
3. It lets each token use information from the other relevant tokens in the context (e.g. working out what "it" refers to).
4. It generates the most probable continuation, not a verified fact; a fluent wrong answer can be highly probable, especially for things it saw rarely or never.
